# Presentation (always on)

**Scope.** These rules govern the containers around prose: tables, lists, headings, and code. The plain-language rule governs the sentences inside them. A template that mandates a structure wins over these rules. Verbatim blocks and signoff quotes stay byte-exact.

## Tables
- Use a table when two or more items share the same two or more attributes. When each item is one fact, use a list.
- Keep a cell to one line. A command longer than one line, or one that contains a pipe, goes in a fenced block. The cell points to the block.
- Never leave a cell empty. Write "none" or "n/a".
- Keep the entries of one column the same kind of phrase.

---

## Lists
- Number a list only when the order matters. Otherwise use bullets.
- A one-step procedure is one bullet, not a numbered list.
- Keep the items of one list the same kind of phrase.

---

## Headings
- Never skip a heading level.
- Follow a heading with text, never with another heading.
- Add subheadings only when the section has two or more.

---

## Code
- Put a path, command, identifier, or value in inline code inside a sentence.
- Put anything the reader runs or copies in a fenced block. Show its expected output after it.

---

## Labels and references
- Label every table, list, and fenced block. The label is a heading directly above it, or one lead-in sentence naming its contents.
- Refer to a table, list, or section by its heading or name. "Above" and "below" are not references.

*Sources: Google developer documentation style guide, Microsoft Writing Style Guide, Chicago Manual of Style chapter 3, IEEE Editorial Style Manual for Authors.*
