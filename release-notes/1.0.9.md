This release adds an update banner that tells you at session start when planwise or your project's pin is behind. Upgrade now moves two working folders into place, repairs open backlog item files and asks how to map unknown item statuses. Plan lint gains four checks that reconcile `Depends On`, cross-sprint reads, write-sets and Output lines. The backlog and lessons reconcilers can move an id in one verified step. Seventeen feedback issues close with this release, and four more that closed after 1.0.8 are listed here.

## 🔔 Update check

- **An update banner at session start.** With the hooks module loaded, each interactive session checks whether the running plugin, the installed copy or your project's `plugin_version:` pin is behind. When one is, a card above the prompt offers `Update Now`, `Update Later` and `Dismiss`.
- **One button for either update.** `Update Now` runs the plugin update, or `/planwise upgrade` when only the project pin is behind. After a plugin update, the card offers `Reload` in its place.
- **A refused update names the command to run.** Claude Code refuses an update inside a session when the marketplace changed a command the update runs. The card then names that command and shows the `claude plugin update` line to run in a terminal before you restart.
- **The `update_check` option.** Set it with `/plugin configure`. `on`, the default, asks GitHub for the release list at most once every 6 hours. `offline` compares local copies only, and `off` runs no check.

## 🩺 Doctor, upgrade and feedback

- **Working folders move on upgrade.** `plan-build/` moves to `{plans_dir}/Plan-Build/`. `feedback-drafts/` and any loose drafts in `Feedback/` move to `Feedback/Feedback-Drafts/`. `/planwise init` and `/planwise upgrade` never overwrite a file, and they list any file they could not move. A custom `project.feedback_dir` is kept, and doctor names an older layout that is still in use.
- **Upgrade repairs open backlog item files.** On a generated index, upgrade grades each open item file against the item template. It adds a missing `*Created:*` footer, fixes legacy decision, priority and domain lines, and moves frontmatter keys outside the template into Notes.
- **Unknown item statuses get a question.** When an open item carries a status outside the valid set, upgrade asks which valid status to map it to before the writer runs. Your answer is stored as a `status_map` entry.
- **Transferred agent mirrors show in the report.** Under `customization_handoff: report+relocate`, the upgrade banner lists each moved mirror as a `TRANSFERRED` row, and the summary counts `Agent mirrors transferred`. Doctor's keep-in-place row now says that upgrade moves such a mirror under that setting.
- **An up-to-date upgrade clears its verdict cache.** When upgrade finds the project already up to date, it retires the verdict cache for that version pair, as a version change does.
- **Post queued drafts from a card.** `/planwise feedback --post <id>` and `--drafts` show the queued drafts in a preflight card and ask one question per draft: Post, Discard or Keep. Your answer is the consent, so no second confirmation follows.
- **A notice for blocked drafts.** While a draft blocked by the privacy check is not dismissed, the `/planwise` preflight prints `planwise: {n} feedback draft(s) were blocked by the privacy check — review with /planwise feedback --status`.
- **The draft tool carries its own rules.** The feedback draft tool's description states when and how to draft. Its result tells the model the draft is saved and verified, so the model does not read it back.
- **A card press is the consent.** The README states that the card's Post button runs the post script directly, outside the permission check. A `permissions.deny` entry does not stop it.

## 🔁 Backlog

- **Move an id.** `reconcile_lessons.py --renumber OLD NEW` and `reconcile_backlog.py --renumber OLD NEW` move one lesson or backlog item to a new id as one verified transaction. NEW must be free and at or above the next id, and `--file NAME` picks the file when two claim OLD.
- **Approve a placement.** `update_backlog.py --approve-placement PATH` records a destination you confirmed in the item's `placement_approved` list. The backlog loop's `placement` verdict then clears, and step 7 of the backlog handler runs the flag for you.

## ▶️ Run and plan

- **Check 57.** A task's `Depends On` must agree across the task file, the Orchestration and the Sprint Plan. Reviewer Check 137 covers the same rule.
- **Check 58.** A Required Context row under another sprint's folder needs a `**Cross-Sprint Refs:**` field in the task header. Reviewer Check 138 covers the same rule.
- **Check 59.** A task's Sprint Plan write-set rows, its `**Output:**` line and its Expected Output paths must agree.
- **Check 60.** A task's `Depends On` must name the producer of each file its Required Context reads.
- **A User-Action Gate in any plan.** The optional section of the Orchestration and Recovery templates now serves any session that stops for your answer, not only Discovery plans. It is a table: Gate, Blocks Task, Hands the User, Allowed Answers and After the Answer.
- **Drop the code-only task sections.** The build spec key `omit_code_sections: true`, at plan, sprint, session or task level, drops sections such as Schema Pin and Change-Surface Census. Verification Commands stays.
- **Plan-build lint names the missing bodies.** `plan_build.py lint` prints one `MISSING:` line per marker with no body, with its document, headings and occurrence, at most 20 per group.
- **A title must not repeat the task name.** The spec lint rejects a task title that starts with the task's own name and a colon, because the task tables already render `name: title`.
- **Execution Inputs record their retention.** Part 1 of an Execution Input carries a `**Retention:**` header line, and the `retention-threshold` lint grades it.
- **Terminal outputs.** `outputs_coverage.py --terminal NAME...` marks an Output that no later session consumes. It prints as `terminal: NAME` and never counts as unnamed.
- **A wrote-nothing gate that survives peer commits.** The Orchestration template's "this task wrote no path under X" gate adds the paths of every commit since dispatch. A peer session's commit no longer fails it, and this plan's own commit still does.
- **Stored task-id gates take a second key.** A gate that counts rows by a stored task id measures the live table and adds a session-date bound or a unique key prefix. Reviewer Check 082 gains this step.
- **Task runners leave git alone.** The agent guard reports `git stash`, `checkout`, `switch`, `reset`, `restore`, `clean`, `add` and `commit` inside a task-runner, and refuses them under `agent_guard: deny`. `stash list`, `clean -n` and `add -N` still pass.
- **One shape for carried flags.** The Master Plan and Sprint Plan templates write each propagated flag block under a `### From {source-session-id} — recorded {date}` heading over a table.

## 🐛 Fixes

- Check 2 of `lint_verification_gates.py` rejected a pre-edit annotation that every other check accepted. It now reads the command's trailing comment and the comment line below it together.
- `lint_verification_gates.py` refused a `Grep` path relative to the project root as missing under the plan root. It now finds the path.
- The backlog route gate read a fixture or evidence path quoted in a Resolution step as a file to create, and returned `placement`. Such a path now reads as a citation.
- A DELEGATED Orchestration got three reference-doc rows in Required Context that its own linter rejects. `scaffold_plan.py` now keeps only the rows the linter accepts, and a DIRECT one keeps all five.
- A section that ran to the end of a file took the file footer with it, and a body could repeat the template's closing separator. The build now keeps the footer with the file, and lint names a body that restates it.
- Gate lint Check 51 reported a `len(` over raw bytes or an item count. It now reports only an operand that traces to decoded text.
- Six sites built the user config folder from the home folder and ignored `CLAUDE_CONFIG_DIR`. Init, upgrade, doctor and the style rules now use the variable when it is set.
- `ei-extractor` could write a cross-tier Note where the `cross-tier-note` lint did not look. It now writes one Note paragraph, with no blank line inside, in the Part that holds the rows.
