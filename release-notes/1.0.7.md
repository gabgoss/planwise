This release lets backlog and run sessions close items from inside a git worktree. Every shipped close command now joins its status value to the flag with `=`. Plan body authoring no longer stops with nothing written on a large session. A lint warning that misread a date as a line band is gone. One feedback issue is closed.

## 🔁 Backlog

- **Close commands run inside a worktree.** Inside a git worktree, Claude Code refuses a Bash command whose argument is the bare word `complete`. The handlers, references and script help now show `--status=COMPLETE` and `--outcome=COMPLETE`, which run everywhere.
- **Usage errors print the runnable form.** `update_backlog.py` and `backlog_loop.py` name the `=` form in their help text and usage errors, so a copied retry runs.

## ▶️ Run and plan

- **Plan bodies are written as they are composed.** `planwise:plan-author` writes each document block to its own file at once and marks the session `partial` after the first write.
- **A long session ends in `PARTIAL`, not in silence.** The author returns `PARTIAL` after 5 document blocks in one dispatch, and its turn limit rises to 80.
- **A dispatch with no status block is resumed.** `/planwise plan` treats a dispatch that returns no `TASK_STATUS:` line as `PARTIAL`. It lints the bodies, then resumes the same author.

## 🩺 Doctor, upgrade and feedback

- **Feedback drafting needs no tool search.** The `draft_feedback` tool is now loaded at session start, so its first call works at once.

## 🐛 Fixes

- The Execution Input lint read a date such as `2026-10-21, lines` as the line band `10-21`. It raised a false `size-band-derivation` warning. Dates no longer match.

## ✅ Issues closed in this release

- [#151](https://github.com/gabgoss/planwise/issues/151) — `planwise:plan-author` writes as it goes and no longer stops at its turn limit with no bodies file on disk.
