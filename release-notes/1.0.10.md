This release makes planwise work inside a git linked worktree. The update check, the config search, the review card, backlog ids and the anchor ledger now find the main checkout. `/planwise run` closes a session through a guarded writer script, and the backlog loop can run an item behind a blocker queued in the same run. Gate lint gains Checks 61 to 65, and a new `review_tier.py` picks the `/code-review` tier for a backlog fix. Five feedback issues close with this release.

## 🌳 Git worktrees

- **Updates find the main checkout's install.** Inside a linked worktree, the update check, `/planwise upgrade` and doctor now match the install Claude Code recorded for the main checkout. Before, the check answered `CURRENT`, Update Now failed, and doctor said the running copy was not the marketplace install.
- **The config search stops at the worktree.** The search for `config.yaml` stops at the first folder that holds a `.git` file or folder. A worktree no longer loads the main checkout's config.
- **Backlog ids never repeat across worktrees.** `parse_backlog.py --next-id` reads the backlog and `Archive/` folders of every linked worktree of the repository. It also reads the item files on disk, so an item filed since the last index write keeps its id. It never reads a remote branch.
- **Feedback drafts stay in the main checkout.** A project in a linked worktree keeps its feedback drafts in the main checkout, so removing the worktree does not delete them.
- **One pending-upgrade marker per project.** The update banner keys its pending-upgrade marker by the main checkout, so every worktree of a project shares it. A marker whose folder is gone is dropped.
- **One anchor-claims ledger per repository.** `resolve_anchor.py --claim` keeps its ledger at the main checkout's root, so two worktrees never claim the same number.

## 🩺 Doctor, upgrade and feedback

- **The review card follows your session.** When the session leaves a worktree that is then removed, a Post press uses the config of the folder the session is in now. It prints one line that names that config.
- **A spent draft clears the card.** When the draft is no longer queued, because it was posted another way, discarded or removed with its worktree, a Post press clears the card and posts nothing.
- **A card clears when another session posts its draft.** The card re-reads the draft file at most once every 5 seconds. It hides when the draft was posted, discarded or expired.
- **Turn off writes the config you are in.** The card's `Turn off` answer writes `feedback.drafts: off` to the config of the folder the session is in, or to the draft's own config when that folder holds none. The card prints the path it wrote.
- **Blocked drafts get their own group.** `feedback_drafts.py list` shows a promoted draft that the privacy check holds under `Blocked by the privacy check`. A draft posted as a comment no longer counts as blocked.
- **Upgrade applies your status answers.** An open backlog item with a status outside the valid set takes the status your `status_map` answer names. An item mapped to COMPLETE or CLOSED moves to `Archive/`. A status with no answer stays as written, and the banner names the fix.

## 🔁 Backlog

- **A blocked item can run behind its blocker.** `backlog_loop.py --init` now queues an item when every open blocker is queued in the same run, and moves each blocker ahead of it. At its turn, an item whose blocker is still open is skipped with the note `blocker-open`. Before, every item with an open blocker was dropped.
- **An item with a user-run step stays out of the loop.** An item whose `## Verification` fence holds a `# user-run:` line is excluded with the reason `user-run verification`.
- **A review tier for each fix.** The new `review_tier.py` reads the working diff and prints a tier: `none`, `low`, `medium` or `high`. In VERIFY, the backlog handler runs `/code-review` at that tier, in the main session only. Add your own code globs under `review_tier.code_globs` in `config.yaml`, and `config_gen.py --migrate` adds the block to an existing config.
- **An absence claim needs proof.** The backlog preflight records every spelling it searched and one positive control for a claim that something is absent. A claim without both reads `absence unproven`, and the planner never recommends a removal that rests on it.
- **The creation process checks files, not the dispatch mode.** Its agents request the foreground. Each step's hand-over file must exist on disk before the next step runs, because the harness may still run an agent in the background.
- **Duplicate-id reports name the fix.** The backlog and lessons duplicate-id reports print the `--renumber` command that resolves them.
- **The `superseded` lesson status.** `superseded` is now a valid lesson status. New configs list it, and `flip_lesson_status.py` accepts it.

## ▶️ Run and plan

- **A guarded closeout writer.** `/planwise run` closes a session with `closeout_session.py`. It sets the Recovery, Orchestration, Sprint Plan and Master Plan statuses, writes the Master Plan tracking row and routes each coordination flag to one destination. It writes only with `--apply`, refuses with no write on any conflict, and changes nothing on a second run.
- **Split-index checks.** A file split into sub-parts carries a `**Split index:**` line that names each sub-part and its sections. `/planwise run` checks it at READ, before each task and at closeout, so a task that lists only the index gets the sub-parts it reads.
- **One owner per session.** The Recovery template carries an `**Orchestrator:**` line. Before each dispatch, `/planwise run` re-reads it and stops when another orchestrator wrote last.
- **An upstream Output check.** `dispatch_preflight.py upstream` resolves each Required Context `Outputs/` path against the files on disk. It reports a renamed file as `drift`, an unwritten file as `missing` and several candidates as `ambiguous`. The Orchestration template runs it before each dispatch.
- **Status block delivery fits the harness.** The spawn skeleton tells a runner to make the status block its final message when the harness hands that message back, and to call `SendMessage` otherwise.
- **Checks 61 and 62.** Gate lint warns when a task's Output line names a file at 90% of a Read limit or more, and the task takes no `measure_files` reading against a ceiling. When several tasks in one folder write such a file, the Orchestration needs a budget line whose terms sum below the headroom.
- **Checks 63 to 65.** Gate lint warns on a criterion that pins a symbol's member count with no instrument on the line. It also warns on a spec line that names `changed` and `added` but no removed case, and on a "before the first write" step in a task that lists no writes in order.
- **Retention grades primary sources only.** The EI extractor marks a cross-sprint reference part as `reference`. Its tokens print as `REFERENCE_TOKENS` and stay out of the retention denominator.
- **Proof runs in the context budget.** The task-file template counts the proof runs a brief demands as their own addend in the context subtotal.
- **A derived tolerance for Check 071.** Reviewer Check 071 compares a shared file's `KiB` figure with a live measurement at 10% and more than 0.1 KiB. Before, it used 15% with no stated derivation.

## 🐛 Fixes

- `/planwise backlog --check` reported an inverted blocks edge when a Related line said the linked item waits for this item. It now skips such a line, and it also reads `waits on`.
- Gate lint Check 18 counted a repository above the plan, such as the main checkout above a worktree, as the plan's repository. It now uses only the nearest one.
- `/planwise upgrade` passed `--task-tools skip` for a declined offer, and the apply step refused it. A declined offer now adds no flag, and when you decline every offer nothing runs.
- Upgrade and doctor called an installed rule that matched an earlier shipped body a stale subset. They now say it matched an earlier shipped body.
- `/planwise review` committed its report with a bare `git add`, so it could commit files another session had staged. It now commits the report by path.
- The structural reviewer collapsed a run of spaces into one dash when it checked an anchored link. A heading with an em dash then read as a broken link. It now writes one dash per space.
- `list_plans.py` read the plans index twice, so a write between the reads could split the drift banner from the table. It now reads it once.

## ✅ Issues closed in this release

These five issues were filed between 2026-11-21 and 2026-11-23 and are fixed in this release.

- [#239](https://github.com/gabgoss/planwise/issues/239) — A split file names its sub-parts on a `**Split index:**` line, and `/planwise run` checks it.
- [#243](https://github.com/gabgoss/planwise/issues/243) — The backlog preflight and planner prove an absence claim with every spelling searched and a positive control.
- [#246](https://github.com/gabgoss/planwise/issues/246) — `/planwise backlog --check` no longer reports an inverted edge for an item that waits for this item.
- [#250](https://github.com/gabgoss/planwise/issues/250) — The spawn skeleton names `SendMessage` only when the harness does not hand back the final message.
- [#251](https://github.com/gabgoss/planwise/issues/251) — The creation process gates each step on its hand-over file, not on the dispatch mode.

This release also ships part of the fix for two open issues: [#171](https://github.com/gabgoss/planwise/issues/171) and [#175](https://github.com/gabgoss/planwise/issues/175). They stay open until the rest of their work lands, as do [#166](https://github.com/gabgoss/planwise/issues/166), [#200](https://github.com/gabgoss/planwise/issues/200), [#201](https://github.com/gabgoss/planwise/issues/201), [#202](https://github.com/gabgoss/planwise/issues/202) and [#213](https://github.com/gabgoss/planwise/issues/213).
