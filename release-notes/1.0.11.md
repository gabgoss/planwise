This release makes plan files carry their own sizes. Required Context tables gain a derived `Role` column, each Orchestration lists its file surface, and Write-Set tables show sizes that the build fills and doctor checks for drift. Gate lint gains Checks 66 to 68, which run a gate and compare it with what the criterion asserts. A backlog loop can now design and build an item in plan mode, and a destructive diff's review gate has three recorded states. Twenty-five feedback issues close with this release.

## ▶️ Run and plan

- **A derived Role column.** `/planwise plan` renders a `Role` cell of `READ`, `EDIT` or `CREATE` in each Required Context table. The build derives it from the task's outputs and the disk, so the spec gains no key. A `CREATE` cell carries `(plan-time estimate)`.
- **A Session Surface block.** Each Orchestration carries a `## Session Surface` table of every file the session's tasks read, with its `Role`, `KiB` and `~Tokens`. A `**Session surface:**` line gives the total for information only.
- **Sized Write-Set tables.** Sprint Plan `## Write-Set` rows carry `Role`, `KiB` and `~Tokens`. Master Plan `### Write-Sets` rows carry `Count`, `KiB` and `~Tokens`, with a `**Write-set total:**` line. The build fills these cells, so nobody writes a size by hand.
- **Drift checks for the derived cells.** `estimate_reconcile.py check` compares 11 more levels for the surface, write-set and master cells, and takes an optional `--config`. An error that stops the check exits 2 with one `ERROR` line.
- **Files Touched in Discovery plans.** Each Consolidated Context part carries a `## Files Touched` section. The last part adds a `## Files Touched Roll-Up` that lists each distinct path once.
- **Two optional sections.** A Sprint Plan can keep a `## Positive-Control Ledger` of reference values a recomputation must reproduce. An Orchestration can keep a `## Scaffold Findings` table. Name either one in `optional_sections` to keep it.
- **A Contract Keys register.** The Master Plan and Sprint Plan templates carry an optional `## Contract Keys` table. The `cross-sprint-touch` lint reports a BLOCKER when a first writer's Step-1 gate omits a literal the register routes to it.
- **An Operational Ceiling Notice.** The spawn-prompt skeleton carries an `## Operational Ceiling Notice` block for a task that trips an edit, context or turn threshold. The post-dispatch checklist states that a `batch_gate.py` exit 2 means the gate did not run.
- **Markers new since the last build.** `plan_build.py lint` and `build` print `ADDED: doc=<ID> marker=<name>` for a missing marker the document lacked at its last build. An `added_since_build=<n>` line gives the total.
- **A plan claims its Resolves items.** `/planwise plan` sets each NOT_STARTED item that the Master Plan's `**Resolves:**` field names to `PLANNING`. The backlog loop then leaves that item to the plan.
- **A plan-mode design pass.** `/planwise plan --plan-mode` designs an interactive Standard plan in Claude Code plan mode. The hooks module answers both plan dialogs, because passing the flag approves that plan.
- **A three-state destructive-diff gate.** `/planwise run` records `SATISFIED`, `DEFERRED (user action required)` or `N/A` for each diff. Only the user's `/code-review ultra` run satisfies the gate. A local `/code-review` does not.
- **Deferral routes the review downstream.** A `DEFERRED` diff routes a coordination flag to the session that first runs the destructive path. That session logs `GATE_PENDING: /code-review ultra` and stops until the user runs the review.
- **Resume messages paste their gates.** A resume message carries each gate from another task's file inline, on a `Gates to re-run:` line with its command and expected value.
- **A deferred-tool fallback.** A task step that names a deferred tool, such as `NotebookEdit`, states the invariant the tool protects and allows a scoped fallback script. A runner that takes the fallback reports it in `KEY_FINDINGS`.

## 🧪 Gate lint

- **Checks 66 to 68.** Check 66 runs a gate and compares the result with its stated `invariant:`, `pre-edit:` or `expect:` value. It runs only in a session the Master Plan marks NOT STARTED or does not track.
- **Check 67 tests paste-ready blocks.** Check 67 runs each After gate over the block under a `<!-- paste-ready: <path> -->` marker. A gate that fails on that block alone is an ERROR.
- **Check 68 flags a blind cut.** Check 68 warns when a command cuts its input at a literal count, such as `head -n N` or `grep -m N`, and asserts no parsed length.
- **More expectation spellings.** Gate lint reads `expect: N` and `MUST be N` as a gate's expectation. Only the upper-case `MUST` counts, so prose that says "must be" is not read as one.
- **Run each new gate once.** `/planwise plan` Step 8e runs each new Before and After gate once before a task is plan-complete.
- **Findings by check.** The third line of the `lint_verification_gates.py` report is `Findings by check:`, with one count for each check and severity.

## 🚦 Review

- **Reviewer Check 140.** The Task Reviewer flags a brief that corrects a figure but keeps a rule whose reason rested on the old figure. It also flags a split count that does not hold row by row.
- **Reviewer Check 141.** The Verification-Gate Reviewer flags a gate literal that no line of the producing task mandates. Each gate cites its producer with a `# producer:` comment.
- **Emitted text in a no-output-change refactor.** A refactor whose contract is no output change now gates on the text it prints. `/planwise review` checks that such a gate exists.

## 🔁 Backlog

- **`--create` allocates its own id.** `update_backlog.py --create --id next` takes the next free id and puts it in place of `NNN` in the first `--files` entry. A lock file stops two concurrent creates from taking one id.
- **A loop can run a plan item.** `backlog_loop.py --init --plan-exit` queues an unrefined Route C item with no large-scope signal as disposition `plan`. The loop designs it in plan mode, then implements it.
- **The session returns to its earlier mode.** After a loop's plan step, the session returns to the permission mode it had before plan mode.
- **An answered close closes the item.** When the user's answer to an open question chooses close, the loop sets the item to `CLOSED` and dispatches no agent. `backlog_loop.py --mark` accepts `--outcome CLOSED`.
- **Placement exclusions say how to clear them.** A loop item excluded for `placement` gets a hint that names an interactive `/planwise backlog <id>` run and `update_backlog.py --approve-placement`.
- **Lesson ids never repeat across worktrees.** `parse_lessons.py --next-id` and `reconcile_lessons.py --next-id` read the lessons folders of every linked worktree. `--renumber` refuses a new id below that floor.
- **Files Touched in the Scope Assessment.** The `/planwise backlog` Scope Assessment shows the item's `## Files Touched` rows, with the primary target first.

## 🩺 Doctor, upgrade and feedback

- **An estimate drift stage.** `/planwise doctor` gains Stage 28, Estimate Drift. It prints each `MISMATCH` line per in-progress plan, or one `no drift` line, and never changes the exit status.
- **Doctor lists blocked feedback drafts.** Doctor Stage 17 prints a `blocked drafts: {n}` row and one row for each `.blocked` sidecar. Doctor never changes a sidecar.
- **Upgrade recommends the to-do list tools.** When the project settings lack `CLAUDE_CODE_ENABLE_TODO_TOOLS`, `/planwise upgrade` recommends adding it. An unattended run now adds the key. A value already present stays.
- **Upgrade re-parents old item headings.** With your consent, `/planwise upgrade` moves each off-template item heading under its core section as an H3. It backs each file up first and keeps every line.
- **A classifier for unplaced headings.** When the synonym table cannot place a heading, the new `backlog-item-classifier` agent drafts a map. In Auto Mode the step writes nothing and prints `Action required:`.
- **The feedback folder on request.** `feedback_drafts.py feedback-dir --config <path>` prints the feedback folder the config resolves to. It writes nothing.
- **The post names its repository.** The feedback preflight card prints a `Target repository:` line from `feedback.repo`, and the per-draft question names that repository.

## 📝 New fill markers

A plan built with an earlier release reports each of these as `ADDED` in `plan_build.py lint` until a body is written.

- The Orchestration's Computed Write-Target Intersection table leaves its `Allocates from` and `Reads from a layer-mate's Output` cells as fill markers.
- The Orchestration's `plan folder` marker replaces `sprint folder`.
- The Orchestration User-Action Gate table gains a `No Answer` marker that says what happens when the user gives no answer.
- The Recovery gate-answers table gains markers for the question, the answer, who answered and the rationale.

## 🐛 Fixes

- Computed write-set intersections compared raw path text, so `./src/x.py` and `src/x.py` read as disjoint. They now compare file keys, and such a pair reads as not disjoint.
- The inline scaffolding path divided the `Retention:` figure by all source tokens. It now divides by primary source tokens, as the Execution Input extractor already did.
- `scaffold_plan.py` rendered Write-Target Intersection rows with fewer cells than the header. Each row now has one cell per column.
- The User-Action Gate table had no branch for an unanswered gate. A `DEFERRED` or `no answer` row in the Recovery file now keeps the gate `OPEN`.
- The Master Plan Hypotheses table now names a task in `Confirmed By`. That task returns CONFIRMED, REFUTED or UNVERIFIED.
- On Windows, gate lint counted some `grep`, `wc`, `ls` and `test` gates differently from a shell. It now starts them with `noglob` in `MSYS`, so they receive the pattern as written.
- A native `Grep` gate with a POSIX class such as `[^[:alnum:]]` matched as a plain character set. Gate lint now translates eight POSIX classes before it matches.
- Gate lint read `\d` in a `grep` gate as a digit. It now reads the letter `d`, as GNU `grep` does without `-P`.
- Gate lint Checks 27 and 34 resolved a path after `git -C <dir>` from the declared working directory. They now resolve it from `<dir>`.
- Gate lint Check 21 flagged a lower-case base placeholder such as `<base-sha>`. Checks 21 and 50 now accept it.
- Gate lint Check 1 reported a vacuous After gate in a session that had begun. It now checks only a session the Master Plan marks NOT STARTED or does not track.
- Gate lint Checks 30, 33 and 35 skipped any line holding the word `WRONG`, even inside a pattern. They now read the label outside quoted arguments and code spans.
- Gate lint closed a fenced block on a marker line with an info string. A fence now closes only on a bare marker line.
- `closeout_session.py` could not find a Meta plan's sprint plan. It now finds either name, and it refuses with `resolve by hand` when both exist.
- A move to COMPLETE kept a stale `awaiting` note on the Status line. `closeout_session.py` and `flip_plan_status.py` now drop it and report `dropped stale note`.
- `dispatch_preflight.py prereq` reported `equal` over an empty listing or a wrong folder. It now prints `not run` and exits 2.
- The `/planwise upgrade` prune offer counted one file fewer per backup pair than the prune deleted. The count now includes the pair's `DISPOSITIONS.md` log.
- `parse_backlog.py --next-id` read an id with an inline comment, such as `id: 047  # split from 012`, as `12`. It now reads `047`.
- An unattended feedback post could comment on a closed issue or one already taken in. It now comments only on an open issue with no `intake`, `resolved` or `wontfix` label.
- A post from the review card ended by saying no person had reviewed it. `feedback_post.py post --consent card` now picks the right closing sentence.
- An unattended post that the privacy check blocked wrote no `.blocked` sidecar. It now writes one.
- A post made as a comment left the promoted draft reading as never posted. Both drafts now get a `.posted` sidecar.
- `/planwise feedback --post` gave the model no command to post or discard a draft. The preflight block now names the `post`, `discard` and `enable-posting` commands.
- In a linked worktree, the `draft_feedback` tool wrote its drafts inside the worktree. It now writes them to the main checkout, so they survive `git worktree remove`.
