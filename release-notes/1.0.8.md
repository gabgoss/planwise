This release lets you post feedback from the card in one press, and it offers verify commands detected from your own test and lint setup. Upgrade now recognises older shipped rule bodies, and doctor reports backlog items that drift from the item template. Plan templates gain Guardrails, a measured-on footer and user-action gate slots, and three new gate-lint checks catch broken count and context gates. Nineteen feedback issues close with this release, and one more closed in 1.0.7 is listed here.

## 🩺 Doctor, upgrade and feedback

- **Post from the feedback card.** The card's Post button runs the new `feedback_post.py` directly, so no model turn starts. The script scans for duplicates, checks the title and the body for private data, and posts a new issue or a comment on the top-ranked match.
- **A verify-command question.** When `build_commands.verify` is absent or empty, the upgrade card offers commands found in your project's test and lint setup. `detect_verify_commands.py` proposes them without writing, and `set_verify_commands.py` stores the ones you accept.
- **Upgrade knows older shipped rule bodies.** A new `manifests/rule-history.json` lists every earlier shipped body of the installed rules. Upgrade refreshes an untouched older copy instead of transferring it as a customization.
- **Preserved agent mirrors move out of the way.** Under `report+relocate`, upgrade transfers an orphaned agent mirror classed PRESERVE to `planwise/upgrade-transfers/` when the plugin ships that agent.
- **Doctor Stage 27 checks item shape.** It lists open backlog items that drift from the item template, such as an unknown status or a stray heading. It is read-only and names `/planwise upgrade` as the repair.
- **Doctor handles a leftover verdict cache.** Doctor reports an unconsumed `upgrade-conflicts/*/verdicts.json`, and the upgrade banner counts it as inert.
- **Unattended privacy blocks leave a record.** A blocked unattended post writes a `.blocked` sidecar beside the draft. `feedback_drafts.py blocked-list` lists them, and `dismiss-blocked` clears one or all.

## 🔁 Backlog

- **Record the fixing commits.** `update_backlog.py --fixed-in <sha>` appends a dated `Fixed in:` line to a completed item. The flag repeats, and `--completes` marks the commit that completed the item.
- **The index checks the `blocks:` graph.** `generate_backlog_index.py` reports an item whose prose waits on an id its own `blocks:` lists, and a `blocks:` cycle of three or more items. It also reports a title that names a file under `.claude/rules/planwise/`. These findings only report.
- **Loop init names the blockers.** An item dropped as blocked lists its open blockers. A `note:` line asks you to check the direction when you also named that blocker. A held item reads `on hold (status BLOCKED)`.
- **One verdict for Open Questions.** `backlog_questions.py --list` and the item shape check now read the section the same way.
- **The route gate warns on unresolved paths.** When no path in an item body resolves under the project root, the route output asks you to rewrite the paths project-relative.
- **Creation agents return their work.** `backlog-author` takes at most 8 items per dispatch, and the creation process checks the index after each one. `backlog-planner` writes a provisional design file, and a planner return with no status block is routed.

## ▶️ Run and plan

- **Caps on generated names.** A new `plan_names` block in `config.yaml` caps folder names at 40 characters, task file names at 80 and paths at 160. The plan writer shortens an over-cap name on a word boundary and refuses a path still over the cap.
- **Scaffolding needs its inputs.** `/planwise plan --scaffold` runs only when the Meta plan's `Outputs/` folder holds a Consolidated Context part. Otherwise it takes the Standard path and prints `Route: Standard`.
- **Guardrails in the Sprint Plan.** A required `## Guardrails` section lists each safety promise with its source, the task step that implements it and the gate that fails without it.
- **Required Context records its measurement.** The build write-back writes a `**Measured:**` footer under each task's Required Context table, with the date, the command, the model and the bytes-per-token ratio.
- **Slots for discovery inputs and user gates.** The Master Plan template has an optional `## Discovery Inputs` section. The Orchestration and Recovery templates have an optional `## User-Action Gate` section.
- **Task runners leave the tree alone.** `planwise:task-runner` and the Spawn-Prompt Skeleton forbid `git stash`, `checkout`, `switch`, `reset`, `restore`, `clean`, `add` and `commit`. The worktree may hold other sessions' work.
- **Briefs carry plan-level ids.** `sprint-scaffolder` copies the definition of each Master Plan id a task names, such as `D2` or `H4`, into the task file.
- **Scaffold agents write as they go.** `ei-extractor` and `scaffold-harmonizer` write each file as they finish it, and the scaffolding gates route a return with no status block.
- **Finished sessions do not stop the build.** The Token Saver scan lists an over-ceiling task in a session the Master Plan marks COMPLETE as already run.

## 🚦 Review and gate lint

- **Check 54.** A task step that reads a path needs a Required Context row for it. The check reports a step that reads a path with no row.
- **Check 55.** A `wc -l` count gate cannot expect more lines than the paths it lists. The check reports an `expect N` above that number as an error.
- **Check 56.** A task step that names a Master Plan id must define it in the task file or list the Master Plan section in Required Context.
- **Gates prove they can fail.** Each verification gate names the defect it catches and records its failure on a planted copy of that defect.
- **A rule change sweeps its other statements.** A prohibition is copied byte for byte into every gate that enforces it, and Reviewer Check 129 now covers a changed or relaxed rule.

## 📚 Leaner references

- The gate, measurement and dispatch references gain new rule sections from recent plan runs. Each section carries one WRONG/CORRECT pair.
- The authoring references keep one WRONG/CORRECT pair per rule section and name the script or test that checks each rule.
- `callout-conventions.md` dropped from 7,022 to 6,285 tokens and `rule-authoring.md` from 11,158 to 10,179. Every heading and section number stays.
- Every shipped reference now passes the strict Markdown lint.

## 🐛 Fixes

- `dispatch_preflight.py overlap` rejected the `--running none` form the Orchestration template prescribes. It now reads `none` as the empty set, for `--running` and `--recoveries`.
- The Orchestration checklist told you to pass this session's own task files to the `outputs_coverage.py` producer run, so it always exited 1. The producer and receiver runs now name the right task files.
- The `build_plan` tool and the plan handler named different folders for the spec and bodies files. Both now use `{planwise_root}/plan-build/<plan name>/`.
- `flag_subject_diff.py` reported a routed flag as unrouted when the task file reworded it. A destination that carries the `Flag {n} from {task}` reference now counts as routed.
- `flag_subject_diff.py` selected no row when a table wrote the short session id `S01-02`. A full session id now also matches the short form, and the script warns when it selects no row from a table that holds rows.
- The Execution Input lint `spec-citation-pair` rejected a Tier 1 source that was not a `.md` file. Any file extension now passes.
- The `cross-tier-propagation` lint fired on Notes that no code consumes. It now checks only a Note that declares its consumer.
- `scaffold_plan.py check-headings` graded a scaffolding Master Plan against the standard template. It now uses the scaffolding template.
- The scaffold agents and the scaffolding handler counted the word `FILL`. They now count `<!-- FILL:` markers.
- Doctor Stage 25 printed one row per mention when one line held the same dead citation twice. It now prints one row with a `(2 mentions)` count.
- The rule comparator quoted permission-mode names in its hand-back, which tripped Claude Code's subagent-output filter. It now paraphrases them.
- `upgrade_run.py` read a verdicts document on stdin in the console code page. It now decodes it as UTF-8.
- `handlers/run.md` now names `planwise:task-runner` where it dispatches the agent.
- The draft-feedback hooks stayed on the session-start folder after a session moved into a git worktree. They now follow the session's current root.
- `feedback_drafts.py list` wrote `status: expired` to disk. It is now read-only.
- The lessons curate workflow searched for status lines with a bare `$`, which matches nothing on CRLF files. It now runs `parse_lessons.py --status promoted --owners`, which reads both line endings.
- The scoped-rule check treated every missing path in an item body as a file to create, so the backlog loop skipped the item. A missing path is now a citation unless its sentence proposes creating it.
- `lint_authoring_frontmatter.py` rejected an exact `Bash(npm test)` entry. It now passes.
